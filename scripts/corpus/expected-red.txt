# Left on 2026-09-09, after asking a different question of this list. Every
# entry above had been checked for "is the matched line real?". None had been

# 2026-09-09, as "a pattern that is essentially only ever present in malware.

# advertised job -- and an invariant test in test/report.test.js now stops it

# Thirteen entries were one missing idea: the file runs on a build agent, a
# release runner or a container the project provisions, and never on the
# machine of the person who cloned the repository -- the only machine this
# tool is asked about. That idea existed in the code as CI_ONLY_DIR and was
# consulted in exactly one place, the high gate of download-and-execute, so
# ssh-backdoor and startup-persistence never asked it; its directory list
# matched exactly one of the thirty-two paths here. It is now a step-down
# beside the test-path one, applied to every rule, one step and no more.

#                             in PUBLIC_KEY into the container's own
#                             authorized_keys, not the host's, and only if the

#   scikit-learn/scikit-learn build_tools/circle downloads the Miniforge
#                             installer and runs it
#
# The other eight stay, and the reason is worth stating rather than hiding:
# they sit in scripts/, tools/, hack/, misc/ and playground/, names that
# guarantee nothing. A dropper a README tells you to run lives in scripts/
# too. truffle, cal.com, cypress, grpc, materialize, beam, airflow and
# minikube are red because their path cannot tell this tool otherwise, not
# because anyone believes those projects are hostile. That is a known limit
# of a path-based rule, recorded here instead of being tuned away with a
# directory list that would also exempt the thing this tool exists to catch.
#
# Two reason lines were also wrong, which is the failure this file can cause
# and the same tell that exposed Scoop, choco and winget-cli. apache/flink
# was listed for an e2e script installing a systemd unit; the file that

# the uv installer from a pinned GitHub release. dotnet/maui was listed for

# eng/devices/run-windows-devicetests.cmd.
#
# Both then moved out of the "CI and test infrastructure" group, because
# neither is that. flink's script is served from the project's docs site for
# users to download and run; the aws-cdk one is sample infrastructure a user
# deploys to their own EC2 instance. They keep their reds on the merits, and
# they are two of the fifteen entries that had looked like CI-only files
